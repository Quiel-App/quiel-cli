# Изменения

Что менялось в `@quiel/cli`, сверху новое. English version — [CHANGELOG.md](https://github.com/Quiel-App/quiel-cli/blob/main/CHANGELOG.md).

Часть записей помечена **Платформа** — это изменения на сервере Quiel, они доехали до вас без обновления пакета. Они здесь потому, что меняют поведение агента, а список только клиентских правок оставил бы это без объяснения.

## 0.8.0 — 2026-09-26

### Добавлено

- **Задача знает, в какой репозиторий пишет.** У проекта может быть несколько репозиториев, а задача до сих пор не говорила, к какому относится, — платформа брала первый попавшийся, и pull request по фронтовой задаче мог молча уйти в бэкендовый. Теперь в карточке есть поле репозитория (появляется, только если их больше одного), `create_task` и `plan_task` принимают `repoUrl`, а клиент сообщает, в каком репозитории его собственный чекаут, — и диспетчер перестаёт выдавать агенту работу, которую тот физически не может сделать. **С вашей машины уходит адрес, а не содержимое.** Агент, который ничего не сообщил, берёт задачи ровно как раньше.

- **Агент узнаёт про красный CI, а не догадывается.** Две вещи, которых он раньше не видел. Первая: `testResult: PASSED` — это слова агента про *локальный* прогон, и если проверки GitHub по голове pull request'а красные или ещё идут, ответ на сдачу теперь говорит об этом прямо, с именами упавших проверок. Это предупреждение, а не отказ; жёсткий запрет остаётся настройкой проекта. Вторая: когда сломана *основная* ветка репозитория, задание и `get_context` прямо говорят, что это не последствие его работы и чинить это в рамках своей задачи не нужно, — потому что в боевом проекте `main` был красным несколько дней, и агенты раз за разом шли чинить чужое.
- **Агенту говорят, когда код зависимости мог не попасть в основную ветку.** Задача считается сделанной по статусу, а не по тому, где оказался её код, — и в боевом проекте pull request слили в уже слитую ветку, так что код в `main` не попал, задача закрылась как сделанная, а зависимые пошли работать на пустоту. Зависимость по-прежнему снимается по статусу (обратное правило подвесило бы все проекты, работающие без pull request'ов), но в задании и в `get_context` теперь есть строка с именем подозрительной зависимости, а `report` предупреждает, если твой собственный pull request нацелен на ветку другой задачи вместо основной.
- **Агенту говорят, когда задача вышла за бюджет.** У проекта появился бюджет задачи в живых токенах. Это предупреждение, а не потолок: работу платформа не останавливает. В карточке появляется пометка, менеджерам уходит одно уведомление, а `report` просит агента написать, на что ушёл расход, — задача оказалась крупнее, чем выглядела, или он застрял и ходит по кругу.

### Платформа

Изменения на сервере Quiel — доезжают без обновления клиента.

- **Сломанная основная ветка видна в проекте.** GitHub присылает событие проверки на каждый прогон, в том числе по `main`, — и платформа их выбрасывала, потому что задачи у них нет. Теперь в обзоре проекта стоит баннер с именами упавших проверок, ссылками на их логи и кнопкой, которая открывает уже заполненную задачу на починку. Судим по последнему коммиту ветки: падение, поверх которого уже починили, ничего не поднимает.
- **Задачу можно возвращать автоматически, если CI покраснел после сдачи.** Проверки обычно заканчиваются уже после отчёта: он приходит через секунды после push, а прогон идёт минутами. Новый переключатель проекта — выключенный по умолчанию — разрешает платформе досмотреть голову pull request'а и, когда проверки завершились провалом, вернуть задачу агенту как ревьюер, назвав упавшее. Возврат расходует попытку, как любой другой: три красных сдачи подряд заканчиваются «Провалена».
- **Зависимость, чей код мог не доехать до основной ветки, помечена в карточке.** Рядом с самой зависимостью, а не отдельной панелью: «готова» и «кода нет в main» — два утверждения об одной строке, и второе должно спорить с первым на месте. Только когда платформа знает: pull request'ы есть, базовая ветка известна, и ни один не слит в основную.
- **Когда базовый pull request сливают, платформа напоминает перенацелить открытые поверх него.** GitHub делает это сам только при удалении базовой ветки; иначе слияние уходит в уже слитую ветку и код не попадает в основную. В ленте задачи остаётся пометка, а менеджерам проекта уходит одно уведомление со списком.
- **Во что обошлась задача — в деньгах и по попыткам.** В карточке рядом с токенами теперь стоят деньги везде, где их есть из чего посчитать (ставки заданы, расход от потокенного агента), а у задачи, которую возвращали с ревью, — разбивка по попыткам: одна сумма никогда не говорит, дороже ли вышла переделка. На экране «Расходы» добавился разрез по типам задач, посчитанный по всем задачам периода, а не по десятке самых дорогих.

## 0.7.0 — 2026-09-25

### Добавлено

- **`report` принимает структурированные хвосты.** После почти каждой задачи что-то остаётся, и агенты уже перечисляют это в отчёте — прозой: «Follow-up: инструменты записи — M2-07; OAuth discovery — M4-04…». Прозу нельзя превратить в задачу кнопкой, и через неделю её никто не найдёт. Новое поле `followUps` принимает вместо этого список: у каждого пункта заголовок, тип, приоритет и `kind` — `blocking` («без этого сделанное считать сделанным нельзя») или `later`. Человек превращает их в задачи одним нажатием, и новая задача связывается с исходной сама.

- **Клиент сообщает, чем оплачивается работа агента.** Quiel показывает, во что обошлась задача в токенах, но токены превращаются в деньги, только если известно, кто платит: при подписке предельная стоимость задачи равна нулю. Клиент теперь определяет это по своему окружению и отправляет одно слово — `SUBSCRIPTION`, `API` или `CLOUD`. **Ни ключ, ни имя переменной, ни её значение с вашей машины не уходят**, только вывод. Это догадка, а не факт — Claude Code спрашивает подтверждение, прежде чем ключ API перебьёт подписку, и вы могли отказаться, — поэтому в панели агента её можно поправить, и правка переживает переподключения.

### Платформа

Изменения на сервере Quiel — доезжают без обновления клиента.

- **Красные проверки видно там, где принимают решение.** Платформа видела проверки GitHub и показывала их карточкой выше, но у кнопки приёмки о них не знали: задачи принимались с красным CI, потому что в отчёте агента стояло `testResult: PASSED` — его слова, обычно про локальный прогон. Теперь рядом с кнопкой стоит предупреждение. Предупреждение, а не запрет: жёсткий запрет есть отдельной настройкой проекта и выключен по умолчанию намеренно.
- **Видно, попал ли код задачи в основную ветку.** Задача считается сделанной по статусу, а не по тому, где оказался её код. В боевом проекте pull request открыли поверх ветки другой задачи: базовый слили в `main` раньше, а этот — в уже слитую ветку, и в `main` код так и не попал, хотя задача закрылась как сделанная. Теперь в карточке написано, если слияние ушло в другую ветку или PR закрыли без слияния.
- **Репозиторий для pull request выбирается, а не угадывается.** При нескольких репозиториях GitHub платформа брала первый, и PR по фронтовой задаче мог молча уехать в бэкендовый. Теперь вместо подкинутой монетки — честный отказ с объяснением.
- **Спецификацию, лежащую в репозитории, наконец видно.** Документ можно добавить **путём** — `docs/TZ.md`, — а не текстом или файлом. Платформа хранит адрес, а не содержимое: файл агент открывает у себя. До этого `get_context` отвечал «документов нет» и советовал спросить человека про файл, который агент мог просто открыть.
- **Панель агента «Сейчас».** «В работе» означало три разных вещи: субагент пишет код тридцать минут, сессия зависла, аренда потеряна. Панель их различает: чем занят, сколько идёт работа, молчит ли, что запускал последним.
- **Последнее, что сказал агент, — в карточке задачи.** Заметки о ходе работы лежали во вкладке «Лента», а решение «ждать дальше или вмешиваться» человек принимает, глядя на карточку.
- **Ход работы словами.** Ветка создана, тесты запускали, код отправлен, pull request открыт — и когда. Читается из журнала команд, поэтому говорит, что агент ЗАПУСКАЛ, а не что получилось; отклонённая команда вехой не становится.
- **В ежедневной сводке появилось, что случилось в проекте.** Сдано за сутки со ссылками на pull request, ждёт приёмки, встало, сколько в очереди по ролям. Раздел получают владельцы и администраторы организации и менеджеры проекта.
- **У задачи видно, сколько она заняла.** Три числа, а не одно: в работе, ждала человека, всего. Выводится из переходов статусов, а не со слов агента о своей сессии.
- **Раздел «Расходы» у проекта.** Итоги за сутки, неделю и месяц, десять самых дорогих задач со временем работы, разрез по агентам. Если задать ставки за токены в настройках организации, расход агентов с потокенной оплатой показывается ещё и в деньгах.
- **Хвосты из отчёта превращаются в задачи одной кнопкой.** Список под результатом: отметить нужные и создать — или создать все разом. Созданная задача попадает в бэклог, несёт строку «откуда взялась» и связывается с исходной. У сдачи с оговорками остаток становится отдельной блокирующей задачей вместо возврата всей работы на доработку.

## 0.6.4 — 25 сентября 2026

### Добавлено

- **Список изменений.** До сих пор его не было нигде — ни файла, ни релизов на GitHub, ни страницы, — и обновление пакета ничего не говорило о том, что вы обновляете. Теперь он уезжает вместе с пакетом, лежит на витрине и становится телом каждого релиза. На обновления можно подписаться: **Watch → Releases** на [Quiel-App/quiel-cli](https://github.com/Quiel-App/quiel-cli) шлёт письмо и отдаёт ленту, а npm показывает только последнюю версию.

В самом клиенте больше ничего не изменилось. Выпуски 0.6.0, 0.6.2 и 0.6.3 описаны задним числом — с них эта история и начинается.

## 0.6.3 — 24 сентября 2026

### Добавлено

- **`link_tasks` и `unlink_tasks` принимают список.** После декомпозиции ТЗ связей сразу десятки, и теперь один вызов стоит одного хода модели вместо сорока. Каждая связь применяется отдельно: отказ на одной не отменяет остальные, в ответе результат по каждой строке. Не больше ста за вызов — список длиннее почти наверняка собран не глядя.
- **`get_context(include:['related'])` отдаёт обе стороны связи и её вид.** Раньше агент видел только задачи, от которых зависит сам, и не знал, что его работа кого-то держит; отличить жёсткую `BLOCKS` от «см. также» `RELATES` тоже было нельзя. Теперь `kind` и `direction` есть всегда.

### Исправлено

- **`report` больше не советует повторить вызов, который не может пройти.** Когда задача уже не ваша, ответ гласил «задача осталась за тобой — можно повторить report». Повтор давал тот же отказ, а stop-хук продолжал требовать сдачи: агент не мог ни закончить, ни остановиться. Теперь `report`, `release_task` и `log` узнают такой отказ, снимают задачу с локального учёта и говорят, что делать с уже сделанной работой.
- **Описание тула `report` называет последствия каждого статуса.** Оно не объясняло, что `partial` и `failed` завершают задачу и снимают аренду, — модель выбирала статус, не зная цены.

### Платформа

- **`report(partial)` отправляет задачу на проверку, а не в тупик.** Раньше она уходила в «Ждёт человека», откуда нет пути в «Готово»: готовую работу с двумя оговорками нельзя было принять вовсе. «Принять или вернуть» — это ревью, оно для этого и есть. Автоприёмка на частичную сдачу не распространяется.
- **Видно, чего не хватает.** `nextSteps` из частичного отчёта показывается под результатом, над кнопкой «Принять», а не исчезает в payload события.
- **Агент узнаёт, что потерял задачу, по любой причине.** Предупреждение приходило только при истечении аренды; задачу, забранную лимитом подписки или человеком из интерфейса, снимали молча — и агент продолжал над ней работать.
- **Владелец узнаёт, что очередь стоит, а агент свободен.** Так выглядит агент без будильника — чаще всего после обновления не выполнили `quiel init` заново.

### Обновление

`npm i -g @quiel/cli`, затем переподключить MCP-сервер (`/mcp` в Claude Code). Повторный `quiel init` не нужен: состав файлов не менялся.

## 0.6.2 — 24 сентября 2026

### Исправлено

- **Агент, обновлённый с 0.6.0 без повторного `init`, замолкал вместо простоя.** `npm i -g` меняет бинарь и не трогает `.claude/settings.json`, поэтому будильник из 0.6.0 не появлялся — а stop-хук всё равно отпускал агента. Теперь хук читает конфигурацию и разрешает простой, только если будильник действительно прописан; иначе возвращается прежний опрос по кругу, а человеку прямо сказано выполнить `init`.
- **Отказ сервера больше не загоняет агента в цикл.** Хук не отличал «работы нет» от «не смог спросить» и требовал задачу, которую не получалось запросить.
- **`waitSec` обещал 300 секунд, а в коде было 90.** Модель строит поведение по описанию, и расхождение здесь дороже опечатки. Потолок снижен до 110 секунд: при 600 появлялось окно, где сервер уже выдал задачу, а вызов убит клиентским таймаутом — задача в работе, а аренду никто не держит.
- **`parseRoles` делил только по запятым** — роли через пробел читались как одна.

### Платформа

- **Задача с существующей арендой больше не кандидат на выдачу.** Одна осиротевшая строка аренды роняла диспетчер на уникальном индексе, и он отвечал `internal_error` на **все** задачи проекта.

## 0.6.1

Не публиковалась. Версию подняли в репозитории, и до релиза её сменила 0.6.2.

## 0.6.0 — 24 сентября 2026

### Добавлено

- **Агент простаивает вместо опроса по кругу и просыпается, когда появляется работа.** Опрос стоил хода модели каждые полторы минуты — за ночь пустой очереди это десятки пустых обращений и раздутый контекст. Ожидание стоит соединения и пары байт. Нужен повторный `quiel init`: будильник — это хук, а обновление пакета хуки не пишет.
- **Инструменты планирования для агента с ролью менеджера**: `link_tasks` / `unlink_tasks` для зависимостей, `plan_task` для правки любой задачи проекта без аренды и `dependsOn` в `create_task`, чтобы связи ставились сразу при создании.

## Более ранние версии

До 0.6.0 список изменений не вёлся. Версии 0.1.0–0.5.3 выходили, пока платформа ещё строилась, и внешних пользователей у них не было.
